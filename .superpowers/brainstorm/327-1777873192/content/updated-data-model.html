Updated Data Model — Phase 1 Changes

Three service categories + date range booking

bookings — updated columns
id UUID (PK)
customer_id → profiles
category ← NEW
service_type_id → service_types
address, postal_code, lat, lng
num_units (nullable)
earliest_date (nullable) ← replaces preferred_date
latest_date (nullable)
preferred_slot: MORNING | AFTERNOON | EVENING (nullable)
fault_description (nullable)
urgency: HIGH | MEDIUM | LOW (nullable)
ac_brand, ac_model (nullable)
notes (text, nullable)
status (updated — see below)
rejection_reason (nullable)
category enum: 'MAINTENANCE' | 'FAULT_REPAIR' | 'INSTALLATION'
status enum (updated): 'PENDING' | 'APPROVED' | 'REJECTED' | 'COMPLETED' | 'INQUIRY'
INQUIRY = fault repair submitted (no schedule, owner calls customer directly)
service_types — updated
id, name, description
category: 'MAINTENANCE' | 'FAULT_REPAIR' | 'INSTALLATION' ← NEW
duration_minutes (nullable for fault repair)
price_sgd (nullable — fault/install may be quoted)
active boolean
Example services: "General Cleaning" (MAINTENANCE), "Chemical Wash" (MAINTENANCE), "AC Fault Diagnosis" (FAULT_REPAIR), "Split AC Installation" (INSTALLATION)
contracts ← NEW (Phase 1B)
id UUID (PK)
customer_id → profiles
num_units int
price_sgd numeric (negotiated total for 1 year)
start_date date
end_date date (= start_date + 1 year)
service_interval_months int (default 3)
notes text (nullable)
status: 'ACTIVE' | 'EXPIRED' | 'CANCELLED'
created_at timestamptz
contract_service_dates ← NEW (Phase 1B)
Auto-generated when contract is created — one row per scheduled service visit
contract_id → contracts
due_date date (start + 3 months, + 6 months, + 9 months, + 12 months)
reminder_sent boolean (default false)
booking_id → bookings (nullable — set when service is booked)
invoices ← NEW (Phase 1B)
id UUID (PK)
customer_id → profiles
booking_id (nullable) → bookings
contract_id (nullable) → contracts
amount_sgd numeric
description text
status: 'UNPAID' | 'PAID'
paid_at timestamptz (nullable)
payment_method text (nullable) — e.g. "PayNow", "Cash"
created_at timestamptz
Key design decisions:
• All category-specific fields (fault_description, ac_brand, etc.) live in the bookings table as nullable columns — no separate tables, simpler queries
• Fault repairs create a booking with status INQUIRY — they never enter the scheduling flow unless the owner manually converts them
• Contracts and invoices are Phase 1B — the schema is shown here so we design them together but implement separately
