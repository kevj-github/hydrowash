Admin Dashboard Flow

What the owner sees and does — from pending requests to confirmed daily schedules

A — Manage Bookings  /admin/bookings
PENDING tab (default)
List of new requests, newest first
Each card shows: customer name, service type, preferred date & slot, address, num units, notes
✅ Approve
❌ Reject
Rejecting opens a text box for a reason (sent to customer via email)
ALL BOOKINGS tab
Filterable by status, date range, service type
Owner can also manually mark a job as COMPLETED after the technician finishes on-site
B — Daily Schedule  /admin/schedule/[date]
1
Set car availability — Owner toggles which cars are available for the selected day. e.g. "Car A ✅, Car B ✅, Car C ❌ (in workshop)". Can be set in advance for the whole week.
2
View approved bookings for the day — All APPROVED bookings for that date shown as unassigned job cards. Each shows: address, service type, duration, preferred time slot.
3
Click "Auto-Optimize Routes" button
What happens under the hood:
→ Fetch all job lat/lng + depot lat/lng
→ Call Google Maps Distance Matrix API (travel times between all pairs)
→ Run nearest-neighbour VRP: distribute jobs across available cars, sequence each car's jobs to minimize total travel time
→ Respect preferred time slots where possible (Morning jobs before Afternoon jobs)
→ Calculate estimated start time per job (prev end time + travel time)
→ Return suggested schedule
4
Review suggested schedule — Owner sees each car's job list in order, with estimated times and a summary (total jobs, total travel distance). Can manually drag a job to a different car or reorder within a car if needed.
5
Confirm Schedule
→ Writes rows to scheduled_jobs with exact times
→ Sends email to each customer: "Your appointment is confirmed for [time]."
→ Technicians can now see their job list when they log in
C — Technician View  /technician/jobs
Technician logs in → sees only their car's jobs for today (and upcoming days). Read-only.
