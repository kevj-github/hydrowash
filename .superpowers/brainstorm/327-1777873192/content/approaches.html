3 Approaches for the Ko Gil Aircon System

Choose an architecture — each covers booking, admin dashboard, route optimization, and email notifications

A

Next.js + Supabase + Vercel RECOMMENDED

Single codebase: Next.js App Router for all UI (customer booking form + admin dashboard), API routes for backend logic, Supabase for database + auth, Vercel for deployment.

Pros

  • One repo, one language (TypeScript)
  • Supabase gives auth + realtime + Postgres out of the box
  • Vercel handles deploys, scaling, env vars
  • Fast to build and iterate

Cons

  • VRP optimization in Node.js is workable but not Python-native
  • Supabase has a free tier but costs scale with usage

Stack: Next.js 15 · Supabase (Postgres + Auth) · Google Maps API · Resend (email) · Vercel

B

Next.js (frontend) + FastAPI (backend)

Split architecture: Next.js for UI, Python FastAPI for the backend API and VRP optimization (Python has better OR-Tools / optimization libraries). Two separate deployments.

Pros

  • Python is the best ecosystem for optimization (OR-Tools, scipy)
  • Cleaner separation of concerns
  • FastAPI is fast and well-documented

Cons

  • Two codebases = more complexity
  • Cross-language debugging is harder
  • Overkill for Singapore's job scale (5–15 jobs/day)

Stack: Next.js 15 · FastAPI · PostgreSQL · Google Maps API · Resend · Vercel + Railway

C

SaaS Booking Tool (e.g. Calendly / SimplyBook) + custom admin

Use an existing booking SaaS for the customer-facing scheduling, build only the admin dashboard + route optimization as a custom app.

Pros

  • Booking UX already built and tested
  • Less code to maintain for booking layer

Cons

  • No control over the customer booking flow
  • SaaS tools don't support custom route optimization logic
  • Monthly SaaS fees add up
  • Integration complexity between systems

Stack: SimplyBook.me / Calendly + Custom Next.js admin + Google Maps API
