Data Model

Key database tables and how they relate — Supabase / Postgres

users (Supabase Auth)
Managed by Supabase — extended via profiles table
id UUID (PK)
email
name
phone
role 'customer' | 'admin'
service_types
Owner configures these in Settings
id UUID (PK)
name — e.g. "Chemical Wash"
description
duration_minutes — e.g. 90
price_sgd — e.g. 80.00
active boolean
service_cars
Each car = one team + vehicle
id UUID (PK)
label — e.g. "Car A", "Team 1"
active boolean
bookings ← core table
id UUID (PK)
customer_id → users
service_type_id → service_types
address, postal_code
lat, lng (geocoded)
preferred_date
preferred_slot: MORNING | AFTERNOON | EVENING
num_units (int, e.g. 3 aircons)
notes (text)
status: PENDING | APPROVED | REJECTED | COMPLETED
rejection_reason (nullable)
created_at
daily_car_availability
Owner sets which cars are available per day
service_car_id → service_cars
date
is_available boolean
Unique on (car, date)
scheduled_jobs
Created when owner confirms optimized schedule
booking_id → bookings
service_car_id → service_cars
scheduled_date
scheduled_start_time
sequence_order (int)
optimized_at (timestamp)
app_settings (singleton)
One row — global config
depot_address
depot_lat, depot_lng
company_name
contact_email
Key relationships: booking → customer (many-to-one) booking → service_type (many-to-one) scheduled_job → booking + car (many-to-one each)
